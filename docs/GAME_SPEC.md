# ゲーム仕様

この文書は完成時の製品仕様を定義します。コードに実装済みの範囲はREADMEを参照してください。

## コンセプト

> Discordで通話しながら、重要な判断だけに参加できる協力型セミ放置ローグライトRPG

タスクバーのような横長フィールドで、ヒーローたちは自動的に移動し、通常攻撃と基本行動を行います。プレイヤーはアクティブスキル、ビルド、進行ルート、撤退、高リスクイベントなど、戦況を変える判断へ集中します。

`TBH: Task Bar Hero`の小型表示、自動進行、ビルド構築の考え方を参考にしますが、Discord Heroでは複数人の協力、短時間のセッション、途中参加、通話中の相談を中心に再構成します。

## 設計原則

- 自動戦闘を眺めるだけでも進行する
- プレイヤー操作は結果に意味があるものへ限定する
- ロビー、ビルド編集、戦闘、結果で画面責務を分離する
- クラスは固定された役割ではなく、ビルドの土台として扱う
- 正解のビルドをプリセットとして押し付けない
- 相性のよい選択肢はおすすめ表示で案内する
- 協力は専用ゲージではなく、編成、状態異常、救助、スキル連携で表現する
- 切断や途中参加によって残ったプレイヤーが過度に不利にならないようにする

## 対応人数

- 対応：1～8人
- 推奨：2～6人
- 初期実装の上限：4人
- 人数不足時は切断プレイヤーや空き役割をAIが補助する

## セッション

- 通常遠征：15～25分
- ボスラッシュ：5～10分
- エンドレス：任意撤退
- 途中参加と再接続を許可する
- 全員退出後はルームを停止し、必要なチェックポイントだけ保持する

## 基本ループ

```text
接続
  ↓
ロビー
  ├─ 必要な場合だけビルド編集
  └─ 準備完了
       ↓
自動戦闘
  ↓
レベルアップ時の3択強化
  ↓
ルート投票／イベント判断
  ↓
ボス戦
  ↓
報酬と戦績
  ↓
ロビーへ戻る／再挑戦
```

クラスやロードアウトは毎回選び直しません。前回保存したビルドでロビーへ参加し、変更したい場合だけビルド編集画面を開きます。

## 操作

### 自動処理

- 移動
- 通常攻撃
- 基本ターゲット選択
- 通常アイテム回収
- パッシブ効果
- 敵の基本行動
- 切断プレイヤーの最低限のAI操作

### プレイヤー入力

- 初回のクラス選択
- 装備、スキル、パッシブ、作戦の編集
- 準備状態
- アクティブスキル
- 緊急回避
- レベルアップ強化
- ルート投票
- アイテム使用
- イベント選択
- 撤退投票

## クラスとビルド

### クラスの役割

クラスはキャラクターの根本的な性質を決める「クラスコア」です。クラスだけでパーティー内の役割を固定しません。

クラスコアが決めるもの：

- 基礎ステータスの傾向
- 固有パッシブ
- 固有リソース
- 装備可能な武器や防具の一部
- クラス固有スキルの候補

プレイヤーの実際の戦い方は、武器、装備、アクティブスキル、パッシブ、作戦の組み合わせで決まります。

### ロードアウト

各ヒーローは少なくとも次の要素を持ちます。

- クラスコア
- 武器
- 防具
- 装飾品
- アクティブスキル
- パッシブスキル
- 自動行動の作戦

初回選択時には最低限のスターター装備を自動装着しますが、名前付きプリセットとしては扱わず、すべて自由に変更できます。

### おすすめ表示

プリセットは用意しません。クラスや現在のビルドと相性がよい候補には、おすすめマークを表示します。

おすすめの判定理由には次を使用できます。

- クラス固有特性と相性がよい
- 選択中のスキルや装備と相乗効果がある
- 現在のビルドで不足している機能を補う
- パーティー全体で不足している役割を補う
- 操作や発動条件が分かりやすい

おすすめには理由を表示します。おすすめを選ばない場合も、警告やペナルティは与えません。

### 役割タグ

クラスとは別に、現在のロードアウトから役割タグと能力評価を自動算出します。

役割タグの例：

- 前衛
- 単体火力
- 範囲火力
- 防御
- 回復
- 強化
- 妨害

ロビーではクラス名だけでなく、現在の主要な役割タグを表示します。パーティー全体についても、各能力が十分か、不足しているかを案内しますが、特定クラスの選択を強制しません。

## クラスコア

### ガーディアン

- 高い耐久力
- 攻撃を受けることで蓄積する防御系リソース
- 挑発、バリア、反撃、押し返しを得意とする
- 盾型、妨害型、反撃火力型などを構成できる

### レンジャー

- 高い単体継続火力
- 距離や弱点を利用する固有特性
- 貫通攻撃、クリティカル、弱点付与を得意とする
- 狙撃型、連射型、罠・妨害型などを構成できる

### メイジ

- 炎、氷、雷などの属性を扱う
- 範囲攻撃と状態異常を得意とする
- 属性連携の起点または完結役になれる
- 範囲殲滅型、状態異常型、単体高火力型などを構成できる

### サポーター

- 回復、強化、弱体化を扱う
- 味方の行動やスキル回転を補助する
- 回復だけを強制せず、戦闘支援や妨害にも寄せられる
- 回復型、強化型、弱体化型、戦闘型などを構成できる

## 協力要素

### 属性・状態連携

| 組み合わせ | 効果             |
| ---------- | ---------------- |
| 水濡れ＋雷 | 連鎖感電         |
| 燃焼＋風   | 炎の拡散         |
| 凍結＋強打 | 防御無視ダメージ |
| 挑発＋反撃 | 広範囲カウンター |

特定クラス同士だけで成立させず、装備やスキルによって複数のクラスが連携条件を作れるようにします。

### 救助

HPが0になったプレイヤーはダウン状態になります。一定時間内に味方が救助すると復帰し、救助中の味方は攻撃能力が制限されます。

誰を救助するか、敵を先に倒すかという判断が発生します。全員がダウンすると敗北します。

### パーティー構成

パーティー編成の評価は、クラス数ではなく現在のロードアウトから算出します。

例：

```text
前衛       十分
単体火力   十分
範囲火力   少ない
回復       なし
妨害       十分
```

不足があっても出発を禁止しません。相性のよい装備やスキルへおすすめマークを付け、改善方法を提示します。

六葉のクローバー、葉を集める条件、専用の共有ゲージ、共有必殺技は使用しません。

## 遠征中のビルド

レベルアップ時に候補から1つ選び、遠征終了時にリセットします。

- 通常攻撃の分裂
- クリティカル時の追撃
- 回復時の攻撃効果
- バリア破壊時の爆発
- 状態異常への追加ダメージ
- スキル使用時の味方支援

選択候補は戦闘画面上へ常設せず、選択が必要なときだけオーバーレイ表示します。

## 永続要素

数値差を広げすぎず、主に選択肢を増やします。

- クラスコア
- スキル候補
- 武器と装備効果
- パッシブ候補
- 作戦候補
- 外見
- エモート
- 称号
- 難易度
- 保存済みロードアウト

## リスクとリターン

- 危険ルート
- 呪われた宝箱
- オーバードライブ
- 強化ボス
- 報酬を確定する撤退
- 先へ進むほど上昇する報酬倍率

パーティー全体への効果は投票で決定し、同数時の処理はルールセットに固定します。

## 途中参加と切断

### 途中参加

- 現在の遭遇または安全な合流タイミングで参加する
- 進行度に応じた一時的なレベルや遠征強化を付与する
- 保存済みロードアウトを基準に戦闘へ参加する
- 参加前の報酬をそのまま獲得させない

### 切断

- キャラクターはAI操作へ移行する
- 一定時間はプレイヤー枠を維持する
- 再接続時は同じキャラクターへ復帰する
- 長時間戻らない場合は安全なタイミングで離脱扱いにする

## Discord連携

- Discord表示名とアバター
- Activity参加者の反映
- 招待
- Rich Presence
- ボス撃破や記録更新の共有
- 発話中キャラクターの視覚演出

発話量や声量を戦闘力へ直接変換しません。

## 画面構成

上位画面は次の5つに分離します。

1. 接続画面
2. ロビー画面
3. ビルド編集画面
4. 戦闘画面
5. 結果画面

戦闘中のレベルアップ、ルート選択、イベント選択、撤退確認は別画面へ移動せず、戦闘画面上のオーバーレイとして表示します。

詳細な画面責務と遷移は[`UI_SPEC.md`](./UI_SPEC.md)を正本とします。

## サーバー権威

サーバーが以下を決定します。

- ダメージと回復
- 敵AI
- クールタイム
- 経験値
- ドロップ
- 選択候補
- 勝敗
- 報酬

クライアントが送るのは操作意図だけです。
